# Contributing to LockedIn Labs projects

Thanks for taking a look. Each repository has its own setup, tests, license, and scope; read those files before proposing a change.

- Open an issue for a bug or feature proposal with a minimal reproduction, expected behavior, and the relevant version.
- Keep pull requests focused. Explain the change, link its issue when applicable, and include tests or documentation for changed behavior.
- Run the checks documented by that repository and report the results in the pull request.
- Use synthetic examples. Do not post credentials, customer information, personal data, or protected health information in issues, commits, or screenshots.
- Report suspected vulnerabilities privately through the repository security policy. Do not open a public issue for an undisclosed vulnerability.

Maintainers review contributions for correctness, security, scope, and maintainability. A proposal is welcome, but acceptance is not guaranteed.
