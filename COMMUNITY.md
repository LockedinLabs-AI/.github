# Join the LockedIn Labs community

Start with the project whose problem you understand. Read its README, architecture notes, license, and contribution guide; reproduce its example before proposing a change.

## Ways to contribute

- Report a reproducible bug with a version and a small synthetic example.
- Improve an installation step, an explanation, or an accessibility issue.
- Propose an integration by explaining the interface, trust boundary, and verification path.
- Open a focused pull request with the relevant checks and a clear description of changed behavior.

Use the project's issues for public technical work. Use [private security reporting](SECURITY.md) for vulnerabilities and the [company contact page](https://lockedinlabs.ai/contact/) for partnerships, confidential reviews, or conduct concerns. Do not submit customer records or private logs.

## Membership and access

Anyone can contribute to a public repository without joining the organization. Membership is for people who need an ongoing project role. A maintainer sponsors each request with the repositories, responsibilities, and access needed; an organization owner approves it.

Members use individual accounts with two-factor authentication. Access should be limited to assigned repositories and reviewed when responsibilities change. Becoming a contributor does not grant access to private products, client environments, deployment credentials, or production data.

## Reviewing our work

Each public product should explain how to run it, what its interfaces promise, what its tests cover, and where its limits are. Product demonstrations and private technical reviews are arranged separately. A GitHub star is a bookmark or expression of interest, not an independent security review or customer endorsement.
